 One recipe instead of five tabs

      
Most developer-tool sites make you decode in one tab, paste into another to format, and into a third to query. Flow keeps the data in one place and lets you stack the operations: every step reads the previous step's output, shows its own result inline, and reports an error without disturbing the steps above it. Change an argument and the whole chain re-runs.

      

        

          
 Magic detection

          
Paste something and Flow guesses what it is — a JWT, gzip inside Base64, percent-encoding, HTML entities, a Unix timestamp, CSV, YAML, a URL, a defanged indicator — and offers the step that opens it. Click the chip and keep going: after a Base64 decode that reveals JSON, the next suggestion is to format or query it.

        

        

          
 Recipes that travel

          
A recipe is a small JSON document. Copy it, paste it, or share a link that carries both the recipe and the input in the URL fragment — nothing is stored on a server, and the person who opens the link sees the same chain and the same result.

        

        

          
 Seventy-four operations

          
Encoding (Base64, hex, Base32, URL, HTML, Unicode, binary, ROT-N, gzip, JWT), hashing (MD5, SHA family, HMAC, CRC32, per-line digests), text (case, trim, find and replace, extract, filter, sort, unique, cut, wrap, slugify, strip HTML, count), data (JSON format and JSONPath, YAML, CSV, flatten, SQL and XML formatting, Markdown tables), time, numbers, network (URL parse, query strings, defang, IP conversion, extraction) and password-based AES-GCM encryption.

        

        

          
 Local by construction

          
Every operation is JavaScript in this page, with hashing and encryption done by the browser's Web Crypto API. The input you paste, the keys you type into an HMAC or AES step and the output never leave the tab. The privacy indicator in the header counts network requests the page makes; it stays at zero while you work.

        

      

    


    

      
 Preset recipes

      
Each preset loads a sample input and a recipe that solves a real, recurring problem. Run one, then edit a step or add your own.

 Why chaining beats single-purpose tools

      
Real payloads are layered. A webhook body is JSON inside Base64 inside a URL parameter; a log line contains a token that contains a JSON payload; a CSV export needs cleaning before it can be queried. Doing that with one-shot tools means copying intermediate results between pages, and the copying is where mistakes happen — a trailing newline, a lost character, the wrong field. A recipe removes the copying: the intermediate values are shown but never retyped.

      
The model is the one Unix pipes introduced fifty years ago, with the addition that every stage is visible. base64 -d | gunzip | jq .payload is a Flow recipe with three steps, except you can see what came out of gunzip before jq complained about it.

      
 How errors are handled

      
A step that fails — invalid Base64, a regex that does not compile, JSON that does not parse — reports the reason on its own card and the chain stops there; the steps after it are marked as skipped rather than run against garbage. Fix the argument or the input and the chain resumes. Operations that decode binary data show a hex dump when the result is not text, so a decode that "worked" but produced bytes is not mistaken for a decode that produced a string.

      
 The encryption step, honestly described

      
AES-GCM encrypt derives a 256-bit key from your password with PBKDF2-SHA256 at 310,000 iterations and a random salt, encrypts with a random nonce, and packs salt, nonce and ciphertext into one Base64 string. Decrypt reverses it and fails loudly on a wrong password or altered data, because GCM authenticates what it encrypts. It is a sound way to protect a note or a config snippet you are about to paste somewhere; it is not a replacement for a secrets manager, and the strength of the result is the strength of the password you chose.

A recipe is the ordered list of steps with their arguments, stored as a small JSON document you can copy from the Recipe pane and paste back with the import button. The Share link button in the header goes further: it compresses the recipe and the current input into the URL fragment, which browsers never send to a server, so opening the link reproduces the whole session on the other person's machine without anything having been uploaded.

Each suggestion is scored and the best few are shown. It only suggests; nothing runs until you click.

        

        

          
          
Steps pass text between them. Decoders that produce bytes which are not valid text show them as hexadecimal, and the hex decode and Base64 decode steps accept that back, so binary can be carried through a chain in hex form. Files opened with the upload button are read as UTF-8 text; for hashing large binary files use the hash generator, which streams the file through Web Crypto.

One match is output as its value, several as a JSON array.
