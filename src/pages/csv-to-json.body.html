By default, CSV files treat all data as text strings. When "Smart Types" is enabled, Layerbit's engine automatically detects numerical values (like 42 or 3.14) and boolean values (like true or false) and formats them as native integers, floats, and booleans in the resulting JSON output, rather than wrapping them in quotation marks. It never changes a value to do so: anything with a leading zero (00123), a + sign (+971…), more than 15 significant digits, or a spelling a number would not keep (1.10) stays text. Standard CSV rules dictate that any text containing a comma (like an address: "Dubai, UAE") must be wrapped in double quotes. Our custom lexical parser specifically reads these encapsulation markers, ensuring that internal commas are treated as normal text characters rather than accidental column delimiters.

Why a real parser matters more than you would expect

CSV looks like it can be handled with two string splits, and that assumption is behind a remarkable number of data-corruption bugs. RFC 4180 permits a field to contain commas, double quotes and even line breaks, provided the field is wrapped in quotes with internal quotes doubled. A perfectly legal single record can therefore look like this:

  • 7,"O'Brien, Jr.","He said ""no"" twice","Dubai\nUAE"

Four fields — one containing a comma, one containing escaped quotes, one containing a real newline mid-record. Splitting on commas yields six fragments; splitting the file on newlines yields three "rows". Both are wrong, and both are what naive code produces. This converter uses a proper lexical state machine, so quoted delimiters are treated as data rather than structure. Our CSV guide covers the wider format problems in depth.

Smart type inference

CSV has no type system — every value is text. With Smart Types enabled, numeric and boolean-looking values become real JSON numbers and booleans instead of quoted strings, but only when that changes nothing: postcodes with a leading zero, phone numbers with a + and identifiers longer than 15 digits stay strings automatically, and the per-column type list lets you force any column to text, number or true/false. Turn Smart Types off to keep every value a string.

Union-of-keys on the way back

Converting JSON to CSV, the header row is built from every key seen across all records. Objects with differing shapes — an optional notes field on some rows — produce one complete table rather than silently dropping the columns that only appear later.

Nulls and empties

CSV cannot distinguish an empty string from a null, a missing field or a deliberate blank — there is one representation for all four. If that distinction matters in your domain, agree a sentinel value with the other side or use a format with real types.

The spreadsheet at the other end

A correct CSV file can still be corrupted the moment somebody opens it, because spreadsheet applications run type inference on every cell. None of these are hypothetical:

  • 01234 becomes 1234 — a leading zero has no numeric meaning, so postcodes and account numbers lose digits.
  • A 16-digit number becomes 4.01289E+15 once it exceeds 15 significant digits.
  • 1-5 and 3/4 become dates. So, famously, did the gene symbols SEPT2 and MARCH1 — corrupted so routinely in published genomics data that the naming committee renamed the genes in 2020.
  • In locales where the decimal mark is a comma, Excel expects a semicolon delimiter and opens a comma file as a single column.

This happens on open, not on export: your file is correct until the tool reading it changes it and someone saves. If humans will open the data in a spreadsheet, an .xlsx export avoids the whole category: in JSON → CSV mode, Save .xlsx writes text cells as text (so 00123 keeps its zero) and numbers as numbers.

Formula injection in exports

One security note that catches people out, because the vulnerability is in your output rather than your input. If a cell begins with =, +, - or @, spreadsheets treat it as a formula. An attacker who can store text in your database — a display name, a ticket subject — can plant a payload that executes when an administrator later exports and opens the file. Before writing any user-supplied value, prefix such values with an apostrophe. Quoting the field is not sufficient, because the quotes are consumed by the CSV parser before the spreadsheet sees the value.
