XPath Cheat Sheet: Selecting Nodes, Predicates and the Namespace Trap

XPath is the query language you already have — in every browser, every XML library, Selenium, Scrapy and most ETL tools — and most developers know just enough of it to be surprised when //entry returns nothing. This is the reference we wished existed: the syntax that covers 95% of real queries, the semantics that cause the other 5% of bugs, and the namespace problem explained once and for all.

Layerbit Engineering Published 27 September 2026 11 min read

The short version

  • /a/b is a child step; //b is "anywhere below". @x is an attribute. […] filters.
  • //item[2] is the second item within each parent. (//item)[2] is the second item in the document. They differ constantly.
  • In XPath 1.0 an unprefixed name means no namespace. If the document has a default xmlns, every unprefixed query returns nothing. Bind a prefix, or use local-name().
  • Browsers, Python's lxml default, Java's javax.xml and most scrapers implement XPath 1.0. Functions from 2.0 and 3.1 will not work there.
  • An XPath expression returns one of four things: a node set, a string, a number or a boolean. Know which one you asked for.

Predicates: filtering a step

Square brackets after a step keep only the nodes for which the expression inside is true. The expression can be a comparison, a function call, a nested path (true if it selects at least one node), or a number, which is shorthand for a position test.

ExpressionSelects
//book[@lang='en']Books with a lang attribute equal to en
//book[@lang]Books that have a lang attribute at all
//book[price > 30]Books whose price child, as a number, exceeds 30
//book[title]Books that have at least one title child
//book[not(@lang)]Books with no lang attribute
//book[@lang='en' and price < 20]Both conditions
//book[1]The first book child of each parent
//book[last()]The last book child of each parent
(//book)[1]The first book in document order, overall
//book[position() <= 3]The first three books under each parent
//book[contains(title, 'XML')]Books whose title contains the text
//book[starts-with(@id, 'bk1')]Attribute prefix match
//book[normalize-space(title) = 'XPath']Exact match ignoring surrounding whitespace

The //book[2] versus (//book)[2] distinction is the one that produces "it returns three results when I asked for one". A predicate binds to the step it follows, so //book[2] means "for every node, its second book child". If three author elements each contain two books, you get three results. Wrapping the path in parentheses first collects all books into one set, and then the predicate picks the second.

Note what is not in the list: no matches() for regular expressions, no lower-case(), no string-join(), no for … return. Those arrived in XPath 2.0, and the engines most people actually use — browsers via document.evaluate, Python's lxml by default, Java's built-in javax.xml.xpath, Selenium, Scrapy — implement 1.0. Saxon and BaseX support 3.1; if you need it, check your engine before writing the query.

The namespace trap, explained once

Take an Atom feed:

<feed xmlns="http://www.w3.org/2005/Atom">
  <entry><title>Hello</title></entry>
</feed>

The xmlns on the root declares a default namespace: every unprefixed element in the document — feed, entry, title — belongs to http://www.w3.org/2005/Atom. Now query //entry. In XPath 1.0 an unprefixed name test matches elements with that local name and no namespace. There are none. The query returns an empty set, with no error, and nothing in the syntax hints at why.

Three ways out, in order of preference:

  1. Bind a prefix and use it. Tell the engine that a means http://www.w3.org/2005/Atom, then write //a:entry/a:title. The prefix you choose does not have to match anything in the document; only the URI matters. Every engine has a way to do this — a namespace resolver function in the browser, a namespaces= dict in lxml, a NamespaceContext in Java.
  2. Match on local name. //*[local-name()='entry'] ignores namespaces entirely. It is verbose, and it will also match an entry element from some other vocabulary, but it works when you cannot register a prefix.
  3. Match on both. //*[local-name()='entry' and namespace-uri()='http://www.w3.org/2005/Atom'] is precise without needing a binding.

The same rule applies to attributes, with one twist: unprefixed attributes are never in the default namespace. So //a:link/@href is correct even though a:link needs the prefix — an unprefixed @href is what the document actually contains.

Axes for when the path is not downward

AxisMeaningExample
parent::The parent (.. is shorthand)//title/parent::book

Sibling axes are the workhorse for scraping HTML that has structure but no useful ids: "the paragraph after the heading that says Price" is //h3[normalize-space()='Price']/following-sibling::p[1].

XPath on HTML

Browsers expose document.evaluate() on HTML documents too, and Selenium and Scrapy use XPath on HTML constantly. Two differences from XML. HTML element names are case-insensitive but the DOM stores them in a fixed case, so match what the parser produces — lower-case in an HTML document, which browsers normalise for you. And class is a space-separated list, so [@class='card'] misses class="card featured"; the idiom is [contains(concat(' ', normalize-space(@class), ' '), ' card ')], which is exactly the kind of thing CSS selectors do better. Use CSS for class and id matching and XPath when you need text content, sibling navigation or a predicate CSS cannot express.

Four result types, one mental model

An XPath expression evaluates to a node set, a string, a number or a boolean, and confusion about which you have causes the last class of bug. //book/price is a node set; //book/price > 30 is a boolean that is true if any price exceeds 30; sum(//book/price) is a number; string(//book/price) is the first price as text. Ask yourself which you want before writing the expression, prefix your names when the document has a default namespace, and remember that a predicate binds to the step beside it. That is most of XPath, and all of the parts that go wrong.

Frequently asked questions
