 Markdown in one screen

      
Markdown is a plain-text format that reads naturally as text and converts cleanly to HTML. It is the format of README files on GitHub and GitLab, of most documentation sites, of notes apps such as Obsidian, and of messages in Slack, Discord and many issue trackers. This editor follows GitHub-flavored Markdown (GFM), the most widely used dialect, which adds tables, task lists, strikethrough and automatic links to the original syntax.

A single line break inside a paragraph is ignored in standard Markdown, so hard-wrapped text flows as one paragraph; leave a blank line to start a new one, or end a line with two spaces or a backslash to force a break. The "Line breaks" option treats every newline as a break, which is how GitHub renders comments and issues but not README files.


      
 Why the preview is sanitized

      
Markdown allows raw HTML, so a Markdown document can contain a <script> tag, an onerror attribute on an image or a javascript: link. Rendering untrusted Markdown straight into a page is a classic cross-site scripting hole. This editor converts Markdown with the marked parser and then passes the HTML through DOMPurify, which keeps safe formatting and strips scripts, event handlers and dangerous URLs before anything reaches the page. The copied and downloaded HTML is the same sanitized output, so it is safe to paste into a CMS or an email template. If you build your own Markdown pipeline, sanitize on output in the same way; escaping the input is not enough because Markdown's own syntax produces HTML.


      
 Using the exported HTML

      
Copy HTML gives you the body fragment: headings with stable id attributes for linking, paragraphs, lists, tables and code blocks, with no styles or scripts, ready for a CMS, a blog engine, an email builder or a documentation template. Download .html page wraps that fragment in a complete, self-contained document with a readable typographic style, a light and dark theme that follows the reader's system setting, and no external requests, which makes it suitable for sending as an attachment, archiving or printing to PDF from the browser. The heading ids follow the same rule GitHub uses (lowercase, spaces to hyphens, punctuation removed), so links like #getting-started written for a README keep working.
