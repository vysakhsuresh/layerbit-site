What the numbers mean

A CIDR block such as 10.0.0.0/22 is an address plus a prefix length. The prefix length says how many leading bits are fixed — the network part — and the remaining bits vary across the hosts in the block. Everything this calculator shows follows from that one number, which is why it is worth being fluent in it rather than memorising a table.

Network and broadcast

The network address has every host bit set to 0; the broadcast address has every host bit set to 1. Neither can be assigned to a machine in IPv4. In a /22 the host part is 10 bits, so the block spans 1,024 addresses of which 1,022 are usable. IPv6 has no broadcast address: the all-ones address is an ordinary host, and the all-zeros "subnet-router anycast" address is reserved but routable.

Mask and wildcard

The netmask is the prefix length written as 32 bits: /22 is 255.255.252.0. The wildcard mask is its bitwise inverse, 0.0.3.255, and is what Cisco access lists and OSPF network statements expect. Getting these backwards is the single most common mistake in a hand-written ACL, and it fails silently by matching the wrong hosts.

Address classification

The result marks whether the address is private (RFC 1918 / RFC 4193 ULA), loopback, link-local, multicast, carrier-grade NAT (RFC 6598), documentation, or globally routable. The distinction matters when a block "works" on your LAN but cannot be reached from anywhere else — 100.64.0.0/10 is the classic surprise inside a cloud VPC.

Splitting a block

Choose a longer prefix and the block is divided into equal subnets: a /22 into four /24s, or into sixteen /26s. Each subnet is listed with its own network, host range and broadcast. This is the operation behind VPC subnet planning, and the table can be exported as CSV straight into a spreadsheet.

How the arithmetic is done

Every address is converted to an integer — 32 bits for IPv4, 128 bits for IPv6 — using JavaScript's BigInt, so IPv6 blocks are computed exactly rather than approximated with floating point. The network address is address AND mask, the broadcast is network OR NOT mask, and the size of the block is 2^(bits − prefix). A /48 in IPv6 contains 280 addresses, or 65,536 /64 subnets, and both figures are shown precisely.

Prefix-length ranges follow the specifications: 0–32 for IPv4 and 0–128 for IPv6. Host counts subtract two for IPv4 blocks of /30 and shorter, treat a /31 as two usable addresses per RFC 3021 (the point-to-point convention), and a /32 as a single host. IPv6 usable counts are the full block size, because RFC 4291 reserves nothing at the top of a subnet.

Three mistakes this tool is built to catch

  • A host address where a network was meant. Typing 192.168.1.37/24 is legal, and the calculator tells you the block is actually 192.168.1.0/24. Firewalls and routers vary in whether they accept the host form; some silently normalise it and others reject it, and a config that works on one vendor fails on the next.
  • Overlapping subnets. Use the membership check with the first address of a second block. If it is inside, the two overlap, and the longest prefix will win routing decisions in ways that are very hard to debug from symptoms.
  • An aggregate that is not one. Two adjacent /24s only form a /23 when the first is aligned to an even boundary: 10.0.2.0/24 and 10.0.3.0/24 aggregate to 10.0.2.0/23, but 10.0.3.0/24 and 10.0.4.0/24 do not. The supernet tool computes the smallest block that covers both and says whether it covers anything else as well.
