Converting to JSON is how you see what YAML did

YAML's convenience comes from guessing what you meant, and every guess is a place it can be wrong in a way that does not look wrong in the source file. JSON has explicit types and no implicit conversion, so round-tripping a document through JSON is the fastest way to find out what a parser actually built rather than what you intended to write.

Most of the surprises come from YAML 1.1, which is still the default in PyYAML — by far the most widely deployed implementation. So these are not historical curiosities; they are live in CI pipelines today. Our YAML guide covers each case and the quoting discipline that prevents them.

The Norway problem

YAML 1.1 resolves y, n, yes, no, on and off to booleans. A list of country codes containing NO for Norway silently becomes false. This converter reads YAML 1.2 by default, so NO stays a string; switch to 1.1 to see what PyYAML would produce, and the Checks panel lists every such value with its line in either mode.

Versions and leading zeros

1.10 is a valid float, so it becomes 1.1 and loses a digit — while 1.2.3 stays a string, because two dots cannot be a number. A leading zero can trigger octal parsing, turning 0755 into 493.

Base-60 numbers

YAML 1.1 supports sexagesimal integers, so 22:22 parses as 1342 and 1:30 as 90. Any colon-separated numeric value — times, durations, partial MAC addresses — needs quoting.

Block scalars and the invisible newline

YAML offers two multi-line styles and three chomping modes, and the combination decides exactly which newlines survive. The one that causes real incidents is a trailing newline in a secret:

  • | keeps the internal newlines and exactly one trailing newline.
  • |- keeps internal newlines and strips the trailing one.
  • > folds internal newlines into spaces, keeping one trailing newline.

So an API key written under | becomes "sk_live_abc123\n". Authentication fails, the error says the key is invalid, and you check it character by character — all correct — because the problem is a character you cannot see. Converting to JSON makes it visible immediately as \n in the string. Use |- for anything that must not carry a trailing newline.

Loading YAML is a security decision

YAML supports typed tags, and unsafe loaders will instantiate objects from them — a tag like !!python/object/apply:os.system passed to PyYAML's unsafe loader executes. Always use yaml.safe_load() for any document you did not author, and treat YAML from a user upload, a webhook or a third-party repository exactly as you would treat a pickle: as code, not data.

There is a denial-of-service angle too. Anchors and aliases let a document reference itself repeatedly, and nesting those references multiplies the expansion — the "billion laughs" attack in a few hundred bytes. If you accept YAML from outside, impose a size limit and a parse timeout as well as using a safe loader.

Runs in your browser

Configuration files are precisely the things that contain connection strings, API keys and internal hostnames — a values.yaml or an appsettings file is often the most sensitive text in a repository. Conversion here happens entirely in the page, so nothing you paste is transmitted anywhere.
